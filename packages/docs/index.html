Intracloud Docs

Intracloud is a blog network you publish to by committing a file. There is no account, no form, and no server behind it.

What is Intracloud

Intracloud looks across public GitHub for files named intracloud.md in repos tagged with the intracloud topic, and renders them as one feed at intracloud.tech. Every page is plain prerendered HTML, so links unfurl and posts show up in search.

Your author name, avatar, and bio come from your GitHub account. Your publish date is the moment Intracloud first sees the file, so nobody can backdate a post to climb the feed. An update is just the file's bytes changing.

Publish a post

Two one-time steps.

1. Commit a file named intracloud.md to any public repo:

---
intracloud: 1
title: How I broke prod
tags: [postmortem, databases]
---

Your markdown goes here.

2. Add the repo topic intracloud. It's on your repo's home page, under the gear next to About.

The topic is what makes discovery reliable. GitHub's code-search index is too slow and spotty for new repos, so Intracloud looks you up in the repository-topic index instead, which is quick and dependable. Without the topic, your post may never be found.

A repo can hold many posts. Put each one in its own folder with its own intracloud.md. The next sync picks everything up, usually within the hour.

Frontmatter reference

Only two fields are required. Unknown fields are ignored, not rejected.

FieldRequiredMeaning
intracloudyesAlways 1. Marks the file and sets the schema version.
titleyesThe post title.
summarynoOne line. Falls back to the first ~200 characters of the body.
tagsnoA list. Normalized (lowercased, hyphenated), capped at 5. A tag needs 3+ posts before it gets its own page.
covernoCover image, relative or absolute. Re-hosted automatically.
canonicalnoThe original URL if this is cross-posted.
draftnotrue keeps the post out of the index.

There is deliberately no date, slug, or author field. Those come from Git and your account, so they can't be gamed.

How it works

A scheduled job runs every 30 minutes and:

  • finds repos tagged intracloud and reads each one's file tree;
  • fetches only the intracloud.md files that changed since last run;
  • converts images to WebP and stores them next to the site, so posts don't hotlink and don't break when a source goes away;
  • rewrites links, strips unsafe HTML, and publishes a static build.

The first time your repo is seen, its posts are marked as archived and kept off the front page, so publishing a repo with a back catalog doesn't flood the feed. Posts you add afterward appear on the front page normally.

Terminal CLI

Read posts without leaving your terminal.

# no install needed
npx @intracloud/cli
npx @intracloud/cli read 1

# or install it
npm i -g @intracloud/cli
intracloud search rust
CommandWhat it does
intracloud [latest] [-n N]list the latest posts
intracloud search <query>search titles, summaries, tags, authors
intracloud read <number|url>read a post (number is from the last list)
intracloud open <number|url>open a post in your browser
intracloud author <name>posts by a GitHub user
intracloud tag <tag>posts with a tag
intracloud tagsall tags with counts

Options: --site <url> points at another instance (or set INTRACLOUD_URL), --json gives machine-readable output, -n N sets how many to list.

Feeds & API

Everything is a static file you can fetch directly.

EndpointWhat you get
/feed.jsonthe full feed: every post's metadata (title, summary, tags, author, url, dates)
/search-index.jsona lean index for search (title, summary, tags, author, url)
/rss.xmlRSS of the latest posts
/@owner/repo/post.mdthe raw markdown source of any post (add .md to its URL)

RSS

Point any reader at https://intracloud.tech/rss.xml. The feed carries the latest posts with titles, summaries, tags, and links back to the full articles.

FAQ

How do I delete a post?

Delete the intracloud.md file, set draft: true, make the repo private, or remove the topic. The next sync drops it, and because the published data is rebuilt from scratch each run, it's gone.

How do I update a post?

Edit the file and push. The next sync picks up the new version.

Why isn't my post showing up?

Check that the file is named exactly intracloud.md, has intracloud: 1 and a title, the repo is public, and the intracloud topic is set. Then give it up to an hour.

What about images?

Reference them however you like (relative paths or absolute URLs). Intracloud fetches each one, converts it to WebP, and serves it from its own domain. Images over 10 MB are skipped.
